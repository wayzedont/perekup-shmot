# Перекуп шмота

Симулятор перекупа одежды. Ты в телефоне: покупаешь шмот дешевле в секонде,
на Авитке и в Китае, отличаешь паль от оригинала и продаёшь дороже.

## Как запустить

```bash
npm start          # сервер на localhost:8080, адрес для телефона печатается в консоль
```

Ничего устанавливать не надо: игра собрана на нативных ES-модулях, сборки нет.
Нужен только Node (для сервера и симуляций) или любой другой статический сервер.

С телефона открывается по адресу вида `http://192.168.0.12:8080` — он появится
в консоли при запуске. Телефон и компьютер должны быть в одной Wi-Fi сети.

## Команды

```bash
npm start          # локальный сервер
npm test           # ядро плюс все экраны
npm run test:core  # дымовой тест ядра: данные, детерминизм, миграция сейва, 60 дней
npm run test:views # каждый экран вызывается поимённо на богатом состоянии
npm run sim        # балансовые прогоны всех стратегий со сверкой по коридорам
node sim/run.js 72 60          # 72 прогона по 60 дней (меньше 48 — цифры врут)
node sim/stability.js 144 72   # проверка самих линеек: какие пороги ловят шум
node sim/diag.js careful 48    # один показатель по стратегии на тех же сидах
node sim/staff-run.js 16 35    # сколько стоит помощник и сколько приносит
node sim/showroom-run.js 10 35 # окупается ли шоурум и его обустройство
node sim/inspect-run.js careful 30 1000   # разбор одного прогона
node sim/probe-second.js       # что лежит на завозе в секонде
node sim/inspect-quality.js    # точность осмотра по уровням «Глаза»
```

Отдельные прогоны для помощника и шоурума нужны потому, что обычные боты
отвечают всем покупателям сразу — помощнику у них просто нечего делать.
Там моделируется игрок с человеческим лимитом внимания. По той же причине
среди стратегий есть `busy`: тот же сильный игрок, но не больше двенадцати
переписок в день.

Страница `tools/art.html` показывает всю графику вещей разом — удобно проверять
силуэты после правок.

Автотест интерфейса запускается прямо в игре из консоли браузера:

```js
import('/tools/uitest.js').then((m) => m.run(900))
```

Он жмёт случайные кнопки и ищет на экране `NaN`, `undefined`, `[object Object]`.

Но на случайный тык полагаться нельзя: забытый импорт в карточке выставленной
вещи ронял шкаф, и после падения игра не отвечала ни на что, кроме полоски
«домой», — а кликер туда просто редко доходил. Поэтому `npm run test:views`
вызывает каждый экран поимённо, на состоянии, где есть всё сразу: товар,
объявления, переписки всех видов, заказ, лот, помощник, шоурум, бренд и
живой дроп.

## Как устроен код

```
index.html            оболочка
styles/app.css        всё оформление
src/
  main.js             запуск, действия интерфейса, игровой цикл
  core/               ядро: не знает слова DOM, крутится и в браузере, и в Node
    rng.js            сидируемый ГСЧ — любой прогон воспроизводится по сиду
    state.js          состояние и миграции сейвов
    kernel.js         деньги, опыт, уведомления, переписки
    tick.js           ход времени: часовой и дневной такт, жизнь мира
    economy.js        цены, спрос, ликвидность — все числа баланса здесь
    inspect.js        осмотр по признакам
    notebook.js       записная книжка: по чему палится какая модель
    items.js          создание вещей, скрытые дефекты
    rival.js          Мирон: секонд к открытию и охота за объявлениями
    season.js         итоги сезона: звание, моменты, что переносится
    staff.js          помощник: что умеет и чего стоит
    showroom.js       поток людей с улицы и обустройство места
    brand.js          свой бренд: спрос на дропы, качество, цена
    data/             каталог моделей, категории, прогрессия, контент, онбординг
    market/           авито, секонд, поставщики, лоты, раффлы
    people/           продавцы, покупатели, постоянные клиенты
    actions/          действия игрока
  ui/                 оболочка телефона и экраны приложений
    art.js            параметрическая графика вещей
sim/                  боты и балансовые прогоны
tools/                сервер, тесты, превью графики
legacy/               исходный прототип и его описание — как справочник
```

Ядро чистое: `src/core` не трогает DOM, поэтому один и тот же код гоняют и
игра, и боты. Это то, что делает балансовые замеры настоящими, а не отдельной
моделью рядом с игрой.

## Главное в механике

**Тимур ведёт за руку, но по одному шагу.** Онбординг — не лекция в первую
минуту, а цепочка: про паль он говорит после первого осмотра, про цену —
после первого объявления, про секонд — после первой продажи. Подсказки стоят
в очереди и выдаются не чаще одной в игровой час, чтобы не читать три
сообщения разом.

**Информация стоит времени.** Осмотр идёт по признакам: бирка, швы, подошва,
запах, коробка. Каждый признак — отдельное решение и отдельные минуты. Всё
осмотреть не успеешь: хорошее в секонде разбирают по часам.

**Навык «Глаз» меняет не скорость, а чувствительность.** Новичок не видит
разницы в хорошей копии, опытный замечает, что шрифт на бирке не тот. От этого
доля пали среди купленного падает с 26% до 1–6%.

**Записная книжка копит знание.** Каждый подтверждённый случай — легит-чеком,
спором, претензией — записывается: «у Данок семь палей из девяти палились по
подошве». Дальше книжка сама подсказывает, с чего начинать осмотр.

**У вещи две скрытые правды.** Подлинность и состояние. На фотографиях дефектов
не видно — только на встрече. Поэтому встреча у метро это не просто минус 150 ₽.

**Торг — разговор.** У продавца характер. Маме важно доброе слово, магазину —
аргумент про рынок, тому, кто срочно уезжает, — что заберёшь сегодня. Самый
сильный ход — ткнуть в найденный дефект.

**Продажа пали под видом оригинала — сцена, а не кубик.** Покупатель
спрашивает напрямую, ты врёшь или юлишь, и каждый ответ двигает шанс проверки.

**Постоянные клиенты.** Выполненный заказ превращает подписчика в контакт с
именем, размером и памятью. Он вернётся, заплатит больше и приведёт друзей.

**Мирон играет в ту же игру.** Он приезжает в секонд к открытию: приехал
вместе с ним — выбираешь первым, проспал — лучшее уже у него. И он забирает
объявления, которые ты открыл и бросил: живая переписка и договорённость о
цене защищают, забывчивость — нет. Но рынок к нему так же суров: примерно
каждое шестое его сообщение — это рассказ о собственной осечке. Взял паль за
дорого, получил единицу, завис с партией, перевёл кидале на карту. После
осечки он на время притихает.

**Объявление «скупаю шмот».** Пост в своём канале, поэтому бесплатный:
платит за него выращенная аудитория. Людей всегда немного — от одного до
шести в неделю, больше никто и не разберёт, — но канал меняет не их число, а
то, что они несут. На маленьком канале тащат что попало из шкафа, и
сорок процентов этого паль. На большом везут дорогое и ходовое, а пали
вдвое меньше: тебя читают, знают, что ты проверяешь, и подсовывать
стесняются. Один и тот же час встречи стоит то четыре тысячи, то сорок.

**Помощник покупает время, а не умения.** Он всегда хуже тебя: отдаёт
дешевле и может прозевать паль. Берёт только те переписки, до которых ты не
дошёл пять часов.

**Шоурум — поток без переписки.** Люди заходят с улицы и забирают вещь
молча, платя меньше твоей цены. Каждое вложение в место превращается в
людей на пороге, но продавать им надо что-то иметь.

**Витрина.** Три вещи на подиуме у входа: человек видит их, а не всю
вешалку, и берёт почти не глядя, в моде модель или нет. Поэтому ставить туда
ходовое — значит продать то, что и так уйдёт; витрина нужна, чтобы
вытаскивать залежавшееся. Переставлять можно раз в сутки — то самое
маленькое решение, ради которого стоит зайти утром.

**Свои дропы.** Производство платится вперёд, а точной цифры спроса не будет
никогда: на экране вилка, а правда выясняется по дням. Перепроизводство
бьёт и по этому дропу, и по цене, которую держит твоё имя дальше.

**Коллаб с другим перекупом.** Любого из топа можно позвать в совместный
дроп: он приводит свою аудиторию, но забирает долю тиража и выручки. Свой
дроп приносит больше денег — коллаб даёт объём, отзывы и доверие за вдвое
меньшие вложения. Договор на словах: тот, кто построил имя на миллионы, им
дорожит, а мелкий партнёр может просто перестать переводить деньги. Товар
тогда разойдётся мимо тебя, а производство ты уже оплатил.

**У недели есть форма.** В понедельник и четверг завоз в секонде, а покупают
в пятницу и выходные, когда у людей зарплата и время. Разница небольшая, но
она превращает неделю в план: в начале закупаешься и осматриваешь, к четвергу
выставляешь, на выходных продаёшь. Утренняя сводка говорит прямо, какой
сегодня день.

**Значок «отвечает быстро».** Авитка показывает скорость ответа всем, и со
значком пишут охотнее. Держится, пока ты отвечаешь тем, кто написал; слетает,
если покупатель прождал весь день. Если не писал никто — не слетает, это не
твоя вина.

**Сезон кончается.** 7 сентября — 31 декабря. Потом итоги и новый сезон с
модификатором. Знания из книжки и навыки переносятся.

## Баланс

Проверяется прогонами, а не на глаз. `npm run sim` гоняет четыре стратегии и
сверяет результат с целевыми коридорами:

| Что меряем | Цель |
|---|---|
| Капитал аккуратного в конце | медиана 25 000–90 000 ₽ |
| Раньше третьей недели не разбогатеть | быстрая десятина прогонов не раньше 15-го дня |
| Неудачный прогон на 30-й день не тонет | нижний квартиль не в минусе |
| Удачный прогон на 30-й день не улетает | верхний квартиль до 120 000 ₽ |
| Второй уровень | день 6–18 |
| Застряли надолго | не больше 35% |
| Провалы капитала в середине игры | нет или мельче 10% |
| Рост сильного игрока после 30-го дня | не меньше 1,7× за месяц |
| Банкротств у аккуратного | не больше 6% |
| Банкротств у кредитного маньяка | 20–80% за два месяца, до 100% за сезон |
| Жадный «паль как ориг» против честного | честность не хуже |
| Ленивый, который только подрабатывает | почти ноль |

Четыре меры здесь переписаны после того, как оказались негодными — и это
отдельный урок: мера, которая шумит сильнее правки, не ловит ничего, а
заставляет крутить баланс вслепую. «Рост сильного игрока» считался как
отношение двух медиан и наследовал шум обеих: 1,6× или 2,1× при неизменном
коде. Теперь рост считается внутри каждого прогона, а медиана берётся уже от
них. «Медиана дня
первых 50 000 ₽» прыгала на восемь дней от одной перетасовки случайных чисел
при неизменном коде. «Отношение квартилей капитала» делило на почти ноль и
давало то 1,8×, то 4,5×. «Доля прогонов выше 50 000 ₽» стояла ровно на
медиане распределения, поэтому сдвиг медианы на тысячу рублей менял её на
десять пунктов. Мера, которая шумит сильнее, чем правка, ничего не ловит —
поэтому вместо них стоят медианы в рублях и квартили.

Пятая — «самый быстрый прогон до 50 000 ₽». Минимум по прогонам это по
определению самый удачливый выброс: на одних и тех же данных он гулял от
12-го дня к 22-му. Теперь там десятый процентиль, который отвечает на тот же
вопрос, но про заметную долю прогонов, а не про двух счастливчиков из
полутора сотен.

Прогонов нужно хотя бы 48, а лучше 72: у аккуратного игрока хвост
распределения тяжёлый, и на двадцати прогонах его медиана завышена на десять
тысяч. Сама медиана при 48 и 72 прогонах совпадает до сотен рублей.

Чтобы этот урок не пришлось учить в шестой раз, появился `sim/stability.js` —
он проверяет не игру, а линейки. Один раз гоняет полторы сотни прогонов, потом
считает каждый показатель сорок раз на случайных подвыборках из тех же данных
и сравнивает полосу шума с порогом. Шумная мера сама по себе не беда: если
порог далеко от полосы, проверка честно ловит поломку. Беда — когда полоса
порог пересекает, потому что тогда проверка просто подбрасывает монету.
Сейчас все пятнадцать мер стоят в стороне от своих порогов.

Все числа баланса собраны в `TUNE` в `src/core/economy.js` и в
`src/core/data/progress.js`. Логика при настройке не меняется.
